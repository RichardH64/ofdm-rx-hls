## 3. IP Definition

### 3.1 What the IP does

The IP is a streaming **OFDM baseband receiver** for a simplified 802.11a-style link. It takes raw complex baseband samples from an ADC (in our case, generated by a Python channel model and placed in DDR by the PS) and outputs decoded bits. Besides the standard receive chain, it corrects the main analog front-end impairment that a real radio introduces: **carrier frequency offset (CFO)** caused by the mismatch between the transmitter and receiver local oscillators.

The receiver performs, in order:

1. Frame detection and symbol timing (Schmidl-Cox correlator)
2. CFO estimation and correction (derotation)
3. Cyclic prefix removal
4. 64-point FFT
5. Least-squares channel estimation from a known training symbol
6. Zero-forcing equalization of each data subcarrier
7. 16-QAM hard-decision demapping to bits

All datapath widths are `ap_fixed` typedefs, so the same design can be resynthesized at different precisions. The evaluation will sweep these widths and report BER loss against FPGA resources (fixed-point design-space study).

Domain: wireless communication (Wi-Fi, LTE and 5G NR all use OFDM receivers built from these blocks).

### 3.2 Waveform parameters

| Parameter | Value |
|---|---|
| FFT size N | 64 (all 64 subcarriers used, no guard bands, to keep the design simple) |
| Cyclic prefix N_cp | 16 samples (one OFDM symbol = 80 samples) |
| Modulation | 16-QAM, Gray coded, normalized by 1/sqrt(10) |
| Frame | 1 preamble symbol, 1 training symbol, `num_sym` data symbols |
| Preamble | Two identical halves of length L = 32 (energy on even subcarriers only) |
| Training symbol | Known unit-magnitude BPSK value X_k = +/-1 on all 64 subcarriers |
| CFO range | abs(eps) < 1 subcarrier spacing |

### 3.3 Interaction with the PS

- **Input:** The PS writes one received frame of complex samples into DDR. An AXI DMA (MM2S) streams it into the IP over **AXI4-Stream**. Each 32-bit beat carries one complex sample: I in bits [15:0], Q in bits [31:16], both 16-bit signed fixed point. TLAST marks the end of the frame.
- **Output:** Decoded bits leave the IP over **AXI4-Stream** to a second AXI DMA channel (S2MM), which writes them back to DDR. Each 32-bit beat carries 8 subcarriers x 4 bits. One OFDM symbol produces 8 beats, and TLAST marks the last beat of the frame.
- **Control:** An **AXI4-Lite** register file (HLS `s_axilite`) holds:
  - Inputs: `num_sym` (data symbols per frame), `sync_thresh` (detection threshold), `cfo_bypass` (1 = skip CFO correction, used for the before/after comparison)
  - Outputs: `detected` flag, `d_hat` (detected timing index), `eps_hat` (estimated CFO), `done`
  - `ap_start` / `ap_done` / interrupt from the standard HLS block-level protocol

### 3.4 Mathematical operations

**Received signal model (used by the Python golden model):**

```
x[n]  = IFFT_N(X)[n], with cyclic prefix prepended
y[n]  = exp(j*2*pi*eps*n/N) * (h * x)[n] + w[n]
```

where `h` is a multipath channel shorter than the cyclic prefix, `eps` is the normalized CFO and `w` is AWGN.

**(a) Frame sync, Schmidl-Cox (L = N/2 = 32):**

```
P(d) = sum_{m=0}^{L-1} conj(y[d+m]) * y[d+m+L]
R(d) = sum_{m=0}^{L-1} |y[d+m+L]|^2
M(d) = |P(d)|^2 / R(d)^2
d_hat = argmax_d M(d)   over the window where M(d) exceeds sync_thresh
```

Both sums are updated recursively, so each new sample costs a constant amount of work:

```
P(d+1) = P(d) + conj(y[d+L]) * y[d+2L] - conj(y[d]) * y[d+L]
R(d+1) = R(d) + |y[d+2L]|^2 - |y[d+L]|^2
```

The threshold test is done as `|P|^2 > sync_thresh * R^2` so no divider is needed.

**(b) CFO estimation and correction:**

```
eps_hat = angle(P(d_hat)) / pi
y'[n]   = y[n] * exp(-j*2*pi*eps_hat*n/N)
```

`angle()` is a CORDIC arctangent. The correction is a phase accumulator (NCO) that adds `-2*pi*eps_hat/N` each sample, followed by a sin/cos lookup and a complex multiply. Any constant phase offset left over is absorbed by the channel estimate.

**(c) CP removal and FFT:** drop the first 16 samples of every 80-sample symbol, then

```
Y_k = sum_{n=0}^{63} y'[n] * exp(-j*2*pi*k*n/64),   k = 0..63
```

**(d) Channel estimation (training symbol, |X_k| = 1):**

```
H_hat_k = Y_k_train * conj(X_k_train)
W_k     = conj(H_hat_k) / |H_hat_k|^2        # computed once per frame
```

**(e) Zero-forcing equalization (each data symbol):**

```
X_hat_k = Y_k * W_k
```

The reciprocal is computed once per frame (64 divisions), so the per-symbol path only has one complex multiply per subcarrier.

**(f) 16-QAM demapping**, independently on I and Q with thresholds {-2, 0, +2}/sqrt(10):

```
def slice_axis(v):            # v = real or imag part of X_hat_k
    b0 = 1 if v < 0 else 0                    # sign bit
    b1 = 1 if abs(v) > 2/sqrt(10) else 0      # inner/outer level (Gray)
    return b0, b1
bits_k = slice_axis(real(X_hat_k)) + slice_axis(imag(X_hat_k))   # 4 bits
```

### 3.5 Why these operations suit hardware acceleration

- **Throughput at the sample rate.** At a 20 MS/s Wi-Fi-like rate, the sync correlator needs several complex multiply-accumulates for *every input sample*. That is hundreds of millions of real operations per second before the FFT even starts, which an embedded ARM core running C or Python cannot sustain. In hardware the recursive correlator is a fixed pipeline that accepts one sample per clock (II = 1).
- **Parallelism.** The 64-point FFT has 6 stages of 32 independent butterflies. Equalization and demapping are fully independent across the 64 subcarriers, so they can be unrolled or pipelined freely.
- **Streaming dataflow.** Every stage consumes samples in order and holds at most one OFDM symbol of state. With `#pragma HLS dataflow` all stages run concurrently, so total throughput is set by the slowest stage instead of the sum of all stages.
- **Latency-critical.** Real protocols must finish decoding within microseconds (for example, 802.11 must send an ACK 16 us after a packet ends). A software receiver cannot meet this. A pipelined hardware receiver adds only a few symbols of latency.
- **Fixed-point efficiency.** The operations tolerate reduced precision, so the hardware can use narrow multipliers (DSP48 slices) instead of floating point. Our design-space study quantifies exactly how narrow.

## 4. IP Architecture

### 4.1 Block diagram

```
          AXI4-Lite (control/status)
                    |
DDR -> DMA MM2S ==> [M1 Frame Sync] ==> [M2 CFO Correct] ==> [M3 CP Remove] ==> [M4 FFT (AMD IP)]
        AXI4-Stream       |  sync-info FIFO  ^                                          ||
        (cint16)          +------------------+                                          ||
                                                                                        vv
DDR <- DMA S2MM <== [M7 Demapper] <== [M6 Equalizer] <== coefficient FIFO == [M5 Channel Estimator]
        AXI4-Stream (packed bits)          ^ data-symbol FIFO ===========================+
```

`==>` is an `hls::stream` (AXI4-Stream between the IP and the DMAs, internal FIFOs between modules inside the dataflow region).

### 4.2 Sub-modules

**M1. Frame Sync (Schmidl-Cox detector).**
Runs the recursive P(d) and R(d) update on every sample (II = 1) using a 64-sample delay line in BRAM/SRL. It compares `|P|^2` against `sync_thresh * R^2`, tracks the peak of M(d) within the detection window, and finds `d_hat`. A circular buffer of recent samples lets it then forward the frame starting at the training symbol's cyclic prefix (index `d_hat + 64`).
- In: AXI4-Stream, complex samples from the DMA
- Out: sample FIFO (complex samples from `d_hat + 64` to end of frame) to M2
- Out: sync-info FIFO, one word per frame `{detected, d_hat, P(d_hat)}` to M2
- Out: `detected` and `d_hat` to the AXI4-Lite status registers

**M2. CFO Estimator and Derotator.**
Reads `P(d_hat)` from the sync-info FIFO once per frame, computes `eps_hat = angle(P)/pi` with a CORDIC (`hls::atan2`), then runs an NCO phase accumulator plus sin/cos lookup and one complex multiply per sample. If `cfo_bypass = 1` the samples pass through unchanged.
- In: sample FIFO and sync-info FIFO from M1
- Out: sample FIFO (corrected samples) to M3
- Out: `eps_hat` to the AXI4-Lite status registers

**M3. CP Removal.**
A counter that discards the first 16 samples of each 80-sample symbol and marks the last sample of each 64-sample symbol. It is small but kept separate so the FFT input framing can be tested by itself.
- In: sample FIFO from M2
- Out: FIFO of 64-sample symbols to M4

**M4. FFT (AMD FFT LogiCORE through `hls_fft.h`).**
A 64-point, pipelined streaming forward FFT. Configured once through its config stream (forward, scaling schedule). We use the vendor core instead of writing our own, since the FFT is not the focus of the project and the core is already optimized.
- In: FIFO of time-domain symbols from M3
- Out: FIFO of frequency-domain symbols (Y_0 ... Y_63, natural order) to M5

**M5. Channel Estimator.**
For the first symbol of each frame (the training symbol), computes `H_hat_k = Y_k * conj(X_k)` using the known training sequence stored in a ROM, then `W_k = conj(H_hat_k) / |H_hat_k|^2`. It sends the 64 coefficients to M6 once per frame. For every later symbol it simply forwards Y_k.
- In: FIFO of frequency-domain symbols from M4
- Out: coefficient FIFO (64 complex W_k, once per frame) to M6
- Out: data-symbol FIFO (Y_k of data symbols) to M6

**M6. Equalizer.**
Loads the 64 coefficients into a local register/BRAM array at the start of each frame, then computes `X_hat_k = Y_k * W_k` for every data subcarrier (one complex multiply per sample, II = 1).
- In: coefficient FIFO and data-symbol FIFO from M5
- Out: FIFO of equalized symbols X_hat_k to M7

**M7. 16-QAM Demapper and Bit Packer.**
Slices each X_hat_k into 4 bits using three threshold comparisons per axis (no multipliers), then packs 8 subcarriers into each 32-bit output word and sets TLAST on the last word of the frame.
- In: FIFO of equalized symbols from M6
- Out: AXI4-Stream of packed bits to the S2MM DMA

**Control and status (top-level wrapper).**
The top-level HLS function holds the AXI4-Lite register map, instantiates M1 to M7 inside a `#pragma HLS dataflow` region, and distributes `num_sym`, `sync_thresh` and `cfo_bypass` to the modules that need them.

### 4.3 Interface summary

| Connection | Type | Data carried | Rate |
|---|---|---|---|
| PS/DDR -> M1 | AXI4-Stream (via AXI DMA MM2S) | 32-bit complex sample (I/Q 16-bit), TLAST at frame end | 1 sample per beat |
| M1 -> M2 | FIFO (`hls::stream`) | complex samples from `d_hat + 64` onward | 1 per sample |
| M1 -> M2 | FIFO (`hls::stream`) | `{detected, d_hat, P(d_hat)}` | 1 per frame |
| M2 -> M3 | FIFO | CFO-corrected complex samples | 1 per sample |
| M3 -> M4 | FIFO (AXI4-Stream semantics, TLAST per symbol) | 64 time-domain samples per symbol | 1 per sample |
| M4 -> M5 | FIFO | 64 frequency-domain values Y_k per symbol | 1 per subcarrier |
| M5 -> M6 | FIFO | 64 equalizer coefficients W_k | 1 burst per frame |
| M5 -> M6 | FIFO | Y_k of data symbols | 1 per subcarrier |
| M6 -> M7 | FIFO | equalized X_hat_k | 1 per subcarrier |
| M7 -> PS/DDR | AXI4-Stream (via AXI DMA S2MM) | 32 bits = 8 subcarriers x 4 bits, TLAST at frame end | 8 beats per symbol |
| PS <-> IP | AXI4-Lite | `num_sym`, `sync_thresh`, `cfo_bypass`; status `detected`, `d_hat`, `eps_hat`, `done` | per frame |

### 4.4 Why this modularization

- **Each module matches one equation** in Section 3.4, so each can be unit-tested in C simulation against the Python golden model by saving test vectors at that module's FIFO boundary.
- **Incremental development path:** we can first build M3 -> M4 -> M5 -> M6 -> M7 on perfectly synchronized, CFO-free input from Python, then add M1 and M2 in front. A working receiver exists early and impairment handling is added on top.
- **Parallel work for three people:** one member owns M1 and M2 (time-domain synchronization), one owns M3 to M7 (frequency-domain chain), and one owns the Python model, test vectors, testbenches and the fixed-point sweep scripts. The FIFO interfaces are agreed first so all three can work at once.
- **Concurrency:** inside the dataflow region every module runs at the same time on different samples, which a single monolithic loop would prevent.
- **Ablation and design-space study:** `cfo_bypass` and the per-module `ap_fixed` typedefs let us measure what each correction stage and each bit width contributes to BER and resource usage.

### 4.5 Alternatives considered

| Option | Description | Decision |
|---|---|---|
| A. PS does sync and CFO, IP does FFT + EQ only | Smaller IP | Rejected: sync and CFO correction run on every sample and are the most rate-critical part of the receiver, so leaving them in software defeats the purpose. |
| B. Shared-memory architecture | PS writes the whole frame to DDR; modules pass buffers through memory and exchange commands | Rejected: every module would read and write DDR, adding traffic and latency. OFDM processing is naturally sequential and streaming. |
| C. Fully streaming dataflow (chosen) | AXI4-Stream in/out, FIFOs between modules | Chosen: one sample per clock throughout, minimal buffering, simple module boundaries to test. |
| Own radix-2 FFT vs. AMD FFT core | | AMD core chosen, so effort goes into synchronization, equalization and the fixed-point study. |

### 4.6 Evaluation plan (summary)

- Bit-exact or tolerance-based checks of each module against Python test vectors (C simulation and C/RTL co-simulation)
- BER and EVM versus SNR (0 to 20 dB) under multipath and CFO, with `cfo_bypass` on and off
- Fixed-point sweep of input and datapath widths (about 8 to 18 bits): report implementation loss (extra SNR needed versus floating point at BER = 1e-3) against DSP, LUT, FF and BRAM usage from synthesis
- Latency and initiation interval from the HLS reports

### 4.7 Stretch goals

Pilot-based phase-noise tracking, MMSE equalization, and IQ imbalance correction.
